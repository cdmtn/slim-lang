Что сделать. Интроспекция: Struct.fields() возвращает список { name, type, optional, default, description }; Struct.describe() человекочитаемое описание; Struct.default() собирает пример из defaults; Enum.entries(). Экспорт: Struct.schema() и Type.schema(spec) выдают JSON Schema (draft 2020-12) для struct, enum, массивов, tuple, union, nullable, Map/Set как массивы, встроенных validators (email → format email, uuid → format uuid, positive → exclusiveMinimum 0), полей с ограничениями where, если они уже есть в репозитории; для типов, которые не выражаются, возвращай понятное предупреждение, а не молча ослабляй схему. Импорт: Struct.fromSchema(schema) создаёт проверяющую struct из JSON Schema подмножества, которое Slim способен проверить; неподдерживаемые ключевые слова приводят к явной ошибке. Режим slmc build --emit-schema пишет schema-файлы для всех экспортируемых struct, чтобы фронтенд и бэкенд делили контракт. Тестовые данные: fake(User) и fuzz(User, n) генерируют случайные валидные значения с seed для воспроизводимости и умеют порождать невалидные варианты для негативных тестов.

Конфигурация рантайма: slim.config({ guard, release, onError, color }) как единая точка вместо набора переменных окружения, с чтением из slimconfig.json и обратной совместимостью с SLIM_RELEASE. Типовой комбинатор defineType("Port", int & range(1, 65535)) без ручной функции. trace(fn) возвращает отчёт о числе и суммарной стоимости проверок типов внутри вызова, чтобы находить горячие границы; реализуй счётчики так, чтобы без trace они не стоили ничего.

Тесты: round-trip Struct → schema → fromSchema → verify на корпусе структур, валидация схемы эталонными примерами, детерминированный fake с seed, fuzz находит невалидные случаи, config переопределяет env, trace считает вызовы и не влияет на результат.
