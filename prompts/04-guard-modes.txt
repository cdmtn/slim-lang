Ограничь стоимость Proxy-охраны типизированных объектов в Slim, /home/nihmadev/slim-lang. Сначала изучи guardTypedValue, guardedValues, scopedVariableTypes, __typed_variable__, функции переприсваивания и мутации типизированных переменных в src/external/core.js, места вставки в src/transform.js, test/runtime-types.test.mjs, test/live-nodes.test.mjs, test/struct-features.test.mjs и README про "mutated". Составь фактическую карту: какие значения оборачиваются в Proxy, что проверяется при set/deleteProperty/defineProperty и как работает откат. Сохрани текущее поведение по умолчанию там, где оно документировано и покрыто тестами, текст ошибок "was mutated into type", идентичность объектов (guardedValues кэширует прокси на пару значение/спецификация) и посторонние незакоммиченные изменения.

Замер (prompts/bench/runtime-bench.slim): let o: User = d для объекта из 4 полей стоит около 6000 нс против 1700 нс у чистого verify, то есть Proxy и повторная проверка удваивают и утраивают цену. Каждая запись в свойство такого объекта затем вызывает полный __type_matches__ по всему объекту, то есть O(размер объекта) на каждое присваивание поля, а при массивах внутри ещё и обход массива.

Предложи и реализуй режимы охраны: guard "assign" (проверка только при присваивании самой переменной, без Proxy), "deep" (текущее поведение) и "off". Выбор по умолчанию определи измерением и README, не ломая существующие тесты без явного решения; если поменять умолчание нельзя без ломки, оставь deep по умолчанию и добавь явное включение дешёвого режима. Источники настройки: slimconfig.json (поле runtime.guard), CLI-флаг, и локальный модификатор на объявлении (например unguarded let o: User = d) для горячих путей. Для deep сделай мутационную проверку инкрементальной там, где это можно доказать корректным: при записи в поле проверяй только тип этого поля по схеме struct, а не весь объект; для union, intersection и custom type, где поле зависит от соседей, оставь полную проверку. Объясни в комментарии, почему инкрементальная проверка эквивалентна полной.

Тесты: мутация поля неверным типом откатывается и бросает в deep, не бросает в assign/off, запись валидного значения проходит, delete обязательного поля бросает, вложенный объект и массив push, повторная обёртка того же значения возвращает тот же прокси, режим из slimconfig применяется. Покажи bench «deep старый / deep новый / assign / off» для чтения, записи поля и создания. Прогони npm test.
