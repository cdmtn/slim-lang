Замер: сейчас slmc run --release убирает работу внутри обёрток (let x: int = i падает с 600 нс до 0), но вызов функции с типизированными аргументами и -> int всё ещё стоит около 43 нс против 3 нс у обычной функции, а let o: User = d стоит 12 нс против 0, потому что обёртки остаются в коде, а RELEASE читается из process.env при импорте. Это не стирание, а обход.

Цель: при сборке с --release (флаг сборки, а не переменная окружения запуска) transform не генерирует обёртки проверок вообще. let x: int = a превращается в let x = a, return внутри функции с -> T остаётся обычным return, проверки аргументов не вставляются, аннотации остаются только в jsdoc/d.ts. Явные вызовы пользователя (Struct.verify, verifySafe, new, type, kindof) продолжают работать как обычные функции. Решай, нужен ли отдельный каталог вывода или суффикс, чтобы dev и release сборки не перетирали друг друга; предложи вариант и объясни выбор. SLIM_RELEASE=1 оставь как совместимый путь, но он должен давать ту же сборку, а не только флаг рантайма. Опционально добавь директиву //@keep-checks или модификатор на отдельной границе (например функция, принимающая внешние данные), чтобы выборочно сохранять проверки в release, и покажи пример.

Тесты: исходник со всеми видами аннотаций компилируется в release без единого имени __typed_*__ в выводе (проверка по тексту вывода), поведение программы с валидными данными совпадает с dev, невалидные данные в release не бросают на аннотациях, но бросают на явном Struct.verify, sourcemap остаётся корректным.
